How delivery works

  • Only accepted attendance creates a notification. Repeated syncs do not create another message for the same event.
  • Messages go to the current primary guardian number on the student record. Pending guardian requests do not change that recipient.
  • Offline attendance must sync first. Notifications older than 24 hours are not sent.
  • “Provider accepted” means Semaphore accepted the request, not that the parent has received or read it.

SMS delivery needs server internet and funded provider credits. The queue pauses while your web service sleeps. Uncertain deliveries are held for review rather than resent automatically.

Provider setup

Configure SEMAPHORE_API_KEY and SMS_DELIVERY_ENABLED=true in Render, then redeploy. Use an approved Semaphore sender name; optionally set SEMAPHORE_SENDER_NAME. Enable your school’s notifications here afterward. Never paste API keys into student or guardian forms.
