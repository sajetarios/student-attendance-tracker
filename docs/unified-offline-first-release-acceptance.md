## Target architecture
1. Server-authenticated, versioned, signed bounded offline capability lease per school/account/role/device and browser context. Non-extractable Web Crypto device key, proof of possession, explicit revocation/epoch on logout and switch, server-side checks on upload; no cached reusable bearer credentials or offline privilege escalation. Start with existing 12-hour maximum unless policy explicitly changes; fail closed on expiry, malformed signature/scope, missing storage, suspicious clock rollback or known revocation. Offline remote revocation cannot be known until connectivity resumes. Shared devices require deliberate sign-out/lock and online reauthentication on account switch; no routine separate passphrase for new profiles, but legacy encrypted records may require their original passphrase once for migration. Storage encryption cannot protect an already-unlocked compromised origin/device.
2. Public nonpersonal role shells, explicit allowlisted versioned assets, authorization before decrypt/render, protected per-role scoped snapshots in IndexedDB, minimum necessary data, incremental provisioning automatically after successful online authentication and renewal. Never cache raw authenticated API responses or credential URLs. Atomic shell readiness and fallback retention across upgrades. Reopen same dashboard route; actual server reachability probe (including Render cold start/database availability), distinguish offline from unauthorized; avoid redirect on transient network failure. Read-only cached DH/admin/principal/parent views with last-synced timestamp and online-only mutations disabled. No globally cached personalized HTML.
3. Gatekeeper: native scanner, encrypted authorized roster/photos, manual fallback, original observed time, AM/PM suggestions only when reliable; ambiguous/stale/overnight evidence goes to existing reconciliation. Teacher: scoped roster/schedule snapshots, manual marks, local register finalization intent, read-only cached history, signed offline class QR issuance using bounded preauthorized schedule/date grants and device-bound key. Student: verify signed grant/token, school/subject/date/window/enrollment, replay/duplicate defense locally and authoritative server checks, pending-only local confirmation; no offline final server acceptance. QR validity remains school policy; untrusted device clock/QR forwarding cannot be fully prevented offline, so server reconciliation is mandatory.
4. One durable logical outbox with schema migration/legacy adapters, scoped identity and device, immutable transaction ID and payload, atomic insertion, explicit ack/review/retry state, dependency ordering per register, encrypted data and retained original timestamp, durable confirmed receipt metadata and attempts. Use IndexedDB commit confirmation before UI confirmation. Idempotent server receipt and transaction in same database transaction, no duplicates across tabs/devices; conflict/revision checks and no overwriting verified data. Migrate legacy stores with readback and idempotent mapping; never delete source until verified migrated/acknowledged, never silently discard encrypted records. Distinguish unavailable storage from empty. Request persistent storage best effort; recovery instructions if key/store lost, never guarantee recovery after eviction.
5. Unified sync coordinator, authorized server revalidation, actual reachability, bounded batches, retry exponential backoff+jitter, single-flight cross-tab or durable lease lock, bounded concurrency and fair scheduling, foreground resume online/pageshow/visibilitychange, Background Sync only when supported. No fixed aggressive polling or repeated unchanged snapshot downloads. Persist server-confirmed receipts, last sync and failure attempts. Unknown/rejected/corrupt records remain accessible to correct owner for review; no duplicate notifications.
6. Sync Center: role- and device-scoped counts from actual logical transactions across legacy and new sources; distinguish waiting, syncing, accepted, review, failed/unreadable, offline/readiness, and server reachability. Do not double count drafts/outbox/receipts. Do not report all synchronized until local storage read succeeds and required server acknowledgement obtained. Keep local and optional cloud-forwarding statuses distinct. Retain branding, custom colors, responsive layout, native dashboard paths and current page on reconnect. Manual sync fallback.
7. Server-side authority: existing attendance, enrollment, date-specific policy, revisions, DTR/OB/leave, memoranda and finalization logic; no fabricated punches, no replacement of verified records; parent notifications only after valid finalized subject attendance and deduplicated. No new HRMS or leave-credit operations.
