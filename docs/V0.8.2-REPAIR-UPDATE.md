# v0.8.2 repair update

This release fixes the reported Students/Teachers page mix-up, learner QR display permissions, personal SF2 download rejection, and visual theme consistency. It is a repair release on top of the v0.8.1 feature baseline.

## Fixes

- Corrected malformed HTML nesting that caused `teachersView`, `schedulesView`, and other workspace views to fall outside the school workspace container. The Teachers page now renders its own teacher table instead of the learner roster.
- Kept the Add Student action in the Students workspace for School Administrators and Class Advisers. Subject-only Teachers do not receive student registration privileges.
- Enabled Subject Teachers to see QR previews for learners in their assigned subject classes. The QR image API performs server-side role/designation and assigned-learner checks; it does not grant school-wide roster access.
- Added clear learner-photo states. Actual student/teacher photo files remain in the private `storage` folder and are intentionally not included in this ZIP. Copy that folder from your previous working release. If a referenced image file is missing, re-upload it from an authorized account.
- Corrected the SF2 export permission check so a Subject Teacher can download their own personal monthly copy even though the report is read-only. Department Head export remains restricted; official SF2 collection remains School Administrator-only.
- Improved browser download handling: validates response type and size, handles the filename header, gives success/error feedback, and restores the button state.
- Replaced the green-heavy styling with a calmer navy/blue and cool-neutral theme, and updated PWA theme/cache versions.

## Important role behavior

- School Administrator: can add students and manage the school roster.
- Class Adviser: can add/manage learners only within authorized advisory scope.
- Subject-only Teacher: can view assigned learners and their QR images and download a personal SF2 copy; does not get the Add Student control.
- Teacher roster editing remains limited by assigned-class scope and server-side checks.

## Database

No new database migration is introduced in v0.8.2. Your existing v0.8.1 database and migrations 001–008 are retained. Do not reset the database or run adoption again. Running `npm.cmd run db:migrate` is safe only as an idempotent check with the provided migration runner; it should report existing migrations as already applied.

## Known verification boundary

The Node automated tests, JavaScript syntax checks, HTML structure checks, CSS parsing, and ZIP integrity are performed on this package. The workbook download, PostgreSQL-backed routes, stored photo files, QR rendering, camera hardware, and offline sync still require local verification against your test environment.
