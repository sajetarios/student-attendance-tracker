# Student Attendance Tracker v0.8.1 — Feature Refresh

## Summary

This release consolidates the requested workflow and interface fixes on top of the v0.8.0 role/dashboard baseline. It is a forward update; it does not reset or recreate the database.

## Included updates

- Adds a visible **Add student** shortcut on the administrator dashboard and for Class Advisers who have permission to register learners in their advisory scope.
- Repairs teacher student-edit form field wrappers and keeps edit scope enforced by the server. Subject Teachers can update the permitted learner name field; Class Advisers can update permitted learner placement within their assigned advisory section. School Administrators retain full student management.
- Keeps student roster views scoped to teachers' authorized subject/advisory classes.
- Enables Subject Teachers to create a personal class schedule for their assigned section; the server automatically assigns the teacher to that schedule and checks for overlapping periods.
- Adds the missing School Administrator Gate Keeper monitoring table and date-filtered teacher gate attendance table to the dashboard.
- Adds a Gate Keeper attendance-type selector: Automatic, Learner only, or Teacher only. The scanner recognizes learner `JHS:` QR cards and teacher `TCH:` badges.
- Requires the Gate Keeper to compare and confirm the registered photo before recording teacher gate attendance. The photo receives an accessible confirmation flash animation; reduced-motion preferences are respected.
- Hardens personal SF2 workbook download by checking for a non-empty workbook and using a temporary download link.
- Applies the calm, low-glare theme to Management, Parent, Student, login, registration, and the offline Attendance Desk pages.
- Updates cache-busting references and package version to 0.8.1.

## Database

No new migration is introduced in v0.8.1. The v0.8.0 migration set (001–008) remains the schema baseline. Run the migration command during installation so any baseline migration not yet recorded in the existing test database is applied once by the migration runner. Do not run a database reset or re-adopt the existing schema.

## Privacy and packaging

The package excludes `.env`, `node_modules`, student photos, local backups, and private TLS keys. Copy the existing local `.env` and `storage` contents from the working test installation into the new folder. Copy private TLS key/certificate files separately when HTTPS is used.
